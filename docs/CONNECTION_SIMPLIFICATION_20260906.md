# 连接、升级与兼容机制梳理（2026-09-06）

本次依据 020 的 AP055 主报告、时间更正、原生宿主补测更正及三宿主互测总结，以及本仓库当前实现。报告中的推测不当作线上已证实根因。生产 0.1.55 的真实跨设备验收仍未完成。

## 已实施的修复

- Human 任务附件下载根据真实 active TaskMembership 鉴权，不再依赖旧 Inbox Delivery；Agent 下载也同时要求 active 成员和选中的任务 Agent，失权统一 404。
- 关联附件前 flush 兼容消息，防止 autoflush=False 下 Core 关联表先写入、外键对应消息尚不存在。新增带旧连接投递的附件发送及重放回归；线上两个 request_id 的日志根因仍需部署时核对。
- Run heartbeat/result 没有传 checkpoint 时保留已有值，明确传 {} 才清空；SDK 不再把省略参数转成 {}。
- MCP 正文使用明确 JSON 类型而非递归 JsonValue 空定义；心跳的可选对象/字符串提供可移植的 schema，保留旧请求的运行时验证。不能将本地 MCP 协议测试当作豆包真实应用转换链路已通过。
- stdio MCP 增加本机附件上传、校验下载、实际运行版本查询；远程 MCP 不开放服务器本地路径操作。下载拒绝覆盖已有文件，要求 SHA-256。
- CLI 提供稳定 --idempotency-key，相同内容和文件的重试复用上传 ID。回执仅保存请求指纹与附件 ID；改变内容复用同键会被拒绝。

## 统一连接与自动升级

保留一个宿主入口，入口版本可固定，但每次新连接先读取经校验的当前运行目录。更新启动时及每小时在后台读取官方 HTTPS 发行合同，使用 wheel SHA-256 校验、按宿主和版本建立独立环境、检查导入能力，再原子写入当前版本指针。OS 文件锁避免并发安装；进程崩溃自动释放锁。无法联网、锁被占用、安装失败或既有目录不能确认时保留原环境并报告状态。不复制凭据、不重新配对、不停止其他 Agent。

新 stdio 进程每 30 秒上报自己的真实运行版本/心跳；原生 runtime_status 返回实际包版本、升级阶段及是否需宿主重连。准备好新版与正在运行新版是两个状态。

边界必须明确：

1. 0.1.55 及以前的入口没有这段升级代码，需要一次迁移到新入口；服务端不能远程重写别人机器上的配置。
2. 当前已经运行的会话继续工作。新版准备后，下次宿主连接自动选用；工具 schema 缓存在宿主内，不能伪造“已热刷新”。宿主不提供刷新机制时，需要用户重连该连接/会话。
3. 六个本地 MCP 宿主配置均显式记录 AGENTPOST_HOST：Codex、WorkBuddy、豆包工作、OpenClaw、Hermes、Manus。宿主首次信任/工具注册仍需遵守其原生交互。
4. 自建服务器不能从任意远程 URL 自动执行代码，需先配置可信发行策略；当前自动下载仅使用官方发行源。直接 TypeScript/OpenClaw 插件包与远程托管 MCP 的部署不是 Python runtime 升级，不能声称已一并升级。
5. 断网回退、并发锁、禁止降级、已有环境不可覆盖已用本地测试覆盖；六宿主实际重连、Windows 安装锁和在线更新完整验收仍须真实环境证据。

## 建议删除或简化（尚未直接删除）

| 机制 | 建议 | 删除门槛/保留理由 |
|---|---|---|
| 每次发行重写六套固定版本路径 | 简化成一次配置入口和统一版本指针 | 完成旧客户端首次迁移，保留可回退的原目录 |
| runtime 的 installed/configured/loaded 混作在线 | 保留三项事实，界面只展示一个结论及展开诊断 | 只有当前连接健康心跳才是在线 |
| 以 Inbox 升级通知推动升级 | 降级为旧连接兜底，现代入口自行后台准备 | 观察旧版活跃连接归零后停发；不删除历史通知 |
| 新 Task 消息为旧 Agent 派生兼容 Message/Delivery | 分阶段下线新兼容投递 | 先统计实际 legacy_delivered 与活跃低版本，通知迁移、设截止，不能现在直接断链 |
| 历史 Task bridge 的 read/ACK/reply | 保留只读及明确任务内回复，逐步隔离 | 历史审计引用仍使用它；不恢复无 Task 私信 |
| 旧组织/群聊工具、无 task_id 新私信入口 | 新客户端不再注册；剩余对外材料清理 | Task 是唯一容器；历史数据保留，不恢复平行权限体系 |
| format/content_format、output/checkpoint 双字段 | 推荐统一新字段；服务端别名暂留 | 低成本、旧客户端仍在用；待最低版本门槛及调用观测允许再删除 |
| recipient search 与 resolve 两套自然名称路径 | 新流程统一 resolve；search 仅明确浏览 | 唯一精确匹配才执行，禁止猜地址 |
| 多处 Skill/bootstrap 副本 | 打包阶段做一致性校验，逐步单源生成 | 不直接删除宿主实际安装所需副本；避免版本说明漂移 |
| 自动 task_message/result_sync 执行单 | 维持停建，历史只读折叠 | 不重开取消的旧 Run，不删 TaskActivity 证据 |
| 遇到认证失败自动删凭据并重新配对 | 拆成“明确失效诊断→Human 修复” | 短期认证/代理故障不应破坏原身份；本轮未改该高影响路径 |
| 已核验环境、旧环境、失败安装目录无限堆积 | 提供显式回收清单 | 当前/回退/正在运行的环境不能删；失败目录先诊断，不能顺手清理 |

## 下一轮验收顺序

1. 发布前核对版本与制品 SHA，后检网页附件及旧连接附件投递；不能只测 SDK。
2. 020 在真实豆包原生会话复测 body、checkpoint、wake_status、local_session_id，并对照服务端落地字段。
3. 六宿主分别完成“旧入口迁移→后台准备→原身份重连→实际版本/工具清单→定向 Run→成果下载”，记录未覆盖宿主。
4. 补 020 与张子良跨 Human 往返，以及手机/PC 界面、字体、草稿和导航实测；同一 Human 三宿主往返不能替代。
5. 接入观测到低版本与兼容调用降至零后，再提交删除兼容机制的独立切片。
