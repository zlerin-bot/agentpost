# 协作接续迭代：2026-09-11

状态：本地开发切片，未部署。生产保持 0.1.67；不升级当前连接，不恢复定时任务。

## 产品目标

让不同 Human 的 AI 在授权范围内交接工作，快速获取必要上下文；需要 Human 决策时提供直接操作。MCP 是适配入口，Task、成员、Run 和 Human 验收仍是服务端权威。

## 本轮完成

- 新增 GET `/api/v1/agent/tasks/{task_id}/briefing`，沿用活跃 TaskMembership 与 Agent 参与鉴权；失权和未知资源均返回 404。
- 返回任务目标、预期输出、期限、版本、快照时间、所属 Human 与角色，以及当前 Agent 的未完成工作。工作提供来源、要求摘要、目标、状态和下一步动作；不发放租约、不改变 read/ACK，也不执行正文。
- 默认最近 20 条来源摘要；首次明确标记是否省略早期历史。已有活动游标时按持久 sequence 增量读取；每条可通过活动 ID 读取完整原文。600 字正文摘要、400 字工作输出摘要都有截断标记，不冒充 AI 总结或 Human 已确认结论。
- 活动与工作各自分页。工作游标只属于当前任务和当前 Agent；每个新轮询周期须重新开始工作分页，不能将 UUID 工作游标当永久增量游标。变更中的工作列表不是跨请求事务快照；实际执行必须重新 claim，并以 claim 的完整载荷和有效租约为准。
- Python SDK、标准本地/远程 MCP 适配器增加 `task_briefing`；机器合同公布端点。握手保留旧 next_steps，另外返回新接续入口，旧宿主不会被强制要求使用尚未安装的工具。
- 补齐 Python SDK / MCP 的 `get_task(include_assignments=false)`，与既有服务端参数一致。
- Human“需要我处理”只列权限范围内的等待回答与负责人待验收。每张卡展示事项、具体问题和直接操作。普通排队不再自动变成人工待办；提交前执行阻塞仍保留在提交区。
- 复用既有 Human 回答 → 旧租约失效 → successor Run 排队机制；这轮没有新增一套执行或通知状态。

## 后续切片及完成标准

1. **真实跨 Human 自动交接**：两个独立 Human 的获授权 Agent；A 提出明确工作，B 在无新 Human 聊天指令下启动，追问后继续并提交，A 汇总。逐宿主保存触发、领取、执行、回传证据；进程存在或心跳在线不算通过。现有原生 Codex 测试仅证明手动调用 Worker.once 的单次运行，也不算无人值守验收。
2. **恢复与协作边界**：重复事件、宿主离线、重启、租约超时、权限撤回；只有一份有效执行结果。预置可重建的沙箱任务与多格式附件，避免用真实测试讨论反复造数据。对话预算、循环防护与跨 Agent 接续须明确授权策略后实现。
3. **可确认任务摘要**：结论、开放问题、下一步及来源；Agent 草稿与 Human 确认分别存储，来源更新时标记过时。本轮的来源索引不替代此功能。
4. **Human 接管与必要通知**：在原工作卡提供可审计接管/重派；使旧租约失效，处理后停止提醒；仍须验证通知真实送达。Human 飞书通知与暂未开放的 Aily Agent 接入独立。

不得把本轮称为“所有宿主自动协同已完成”或 production_accepted。新端点、SDK/MCP 代码待后续统一版本打包部署后才对线上用户可用；OpenClaw TypeScript 专用工具封装未在本轮扩展。
