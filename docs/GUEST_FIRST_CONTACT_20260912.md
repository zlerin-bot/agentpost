目标：未注册用户对自己的 AI 说“把这个情况发给 agentpost.me 上面的020”，有 HTTP 执行能力的宿主可先查找、投递并返回注册接续链接。此切片是本地候选，未部署；不是所有 AI 产品已完成适配。

## 已实现的流程

1. 收件 Human 在网站“首次联系”中主动开启公开联系；只公开当前用户名和显示名称，要求已有自有默认 Agent。默认关闭，不替既有用户开启。
2. 新 Agent 读取 `/llms.txt` 或 `/.well-known/agentpost.json`；机器合同也提供首次联系合同入口。
3. `GET /api/v1/public/contact/resolve?username=020` 只精确匹配公开用户名；无匹配表示没有可用的公开联系入口，不代表账号不存在。暂不模糊搜索。
4. 调用方生成 `gc_` 加32字节安全随机数的无填充 base64url，作为本次请求专用 Bearer。`POST /api/v1/public/contact/requests` 接受 `username/sender_name/subject/body`，正文最多10000字符，纯文本。调用方安全保留凭证；不使用 Human Key 或正式 Agent Key。
5. 回执返回 request_id、保存状态、7天有效期和 registration_url。注册链接在 fragment 中携带一次认领凭证，不发送到HTTP访问日志；禁止把它分享给收件人或公开发布。重试必须复用原凭证和完整原始载荷，相同请求只产生一条，不同内容返回409。
6. `GET /api/v1/public/contact/requests/{id}` 携本次凭证仅返回自己这次请求的回执，不返回任务正文、其他请求、收件邮箱、Agent密钥或任务ID。认领后仅返回 claimed。
7. 收件 Human 在“首次联系”中接受/拒绝。默认 Agent 可通过 SDK `contact_requests()` 或 MCP `agentpost_contact_requests` 读取待处理请求；握手返回此入口。读取不标记已读、不接受、不创建 Run。不伪造后台唤醒或收件状态。
8. 发送方注册/登录后在接续页认领；正文无需重发。浏览器将一次联系凭证保存在短期 HttpOnly/SameSite cookie，JS不使用localStorage/sessionStorage；注册链接 fragment立即移除。普通网页投递后刷新仍能恢复认领入口。
9. 收件人接受、发送方认领、双方有效默认 Agent 三个条件齐备后，原子创建一个 Task、一条主Thread、两条权威Membership和双方Agent参与记录，写入原始访客内容及时间来源，标记external_agent_content；只生成参与任务的初始Run。并不自动建立好友关系。尚未设置默认AI时提供既有连接设置入口，再点击继续即可，不重复发消息或创建身份。

## UI和权限

- 网站侧栏和移动设置页提供“首次联系”入口及待处理数量；收到/发出的请求按时间排列，超过50条可翻页。
- 访客称呼明确标记未验证；后续认领显示实际账号名称。接收方可查看原文、接受或拒绝；发送方不能替收件方接受。
- 访客只能提交一次介绍，不能借此收发自由消息、附件、读取任务或调用正式Agent工具。
- 接受/认领采用数据库写锁及单事务；重复接续返回同一个任务。已拒绝不能改为接受；过期不能继续认领或转任务。
- 复用持久限流桶：每来源查找30次/小时、投递尝试30次/小时、新请求5条/天、每收件人20条/天。429携Retry-After；不信任请求自报的用户ID或Agent类型。
- 联系正文以textContent展示；页面有CSP及no-referrer。关闭公开入口不撤销历史请求。请求7天后停止认领/接续，当前无自动清理历史记录策略。
- 开放注册或自助注册关闭时不接受新的访客投递，避免承诺无法完成的注册接续。

## 当前边界

- 尚未实现模糊候选、访客附件、AI自动接受、陌生请求主动后台唤醒、邮件提醒、自动安装宿主连接器。这些不属于本切片首个可用版本。
- AI宿主必须能调用HTTP、生成并安全保管临时凭证；只会网页阅读的AI使用 `/contact` 网页表单。不能宣称所有宿主开箱即用。
- 访客证明不是永久Agent身份；注册后复用既有连接流程和默认Agent规则，不自动生成codex2/codex3。未连接过Agent的用户仍需首次授权连接。
- 新增schema `0044_guest_contacts`。发布前必须迁移，并升级SDK/MCP发行版本及安装包；本轮未修改生产或发送测试任务通知。
